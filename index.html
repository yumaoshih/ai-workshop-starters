下一次開工前 / SYNC

老師更新了，A 怎麼拿到？

把 Fork 想成影印一份講義：老師後來修改母片時，A 的影本不會自動改變。Sync fork 就是把老師最新版補進自己的副本。

取得老師更新｜上游 → 自己
老師 upstream/main→Sync fork → Update branch→A 的 fork/main
提交自己的修改｜自己 → 上游
A 的作品→Pull Request→老師 upstream/main
  1. 打開自己帳號下的 Fork
  2. 按 Sync fork
  3. 確認後按 Update branch

開工前先 Sync，完成後再 PR。

看到 Conflict 怎麼辦？ 代表雙方修改到相同內容；先保留自己的作品並請老師協助，不要使用 Force 強制覆蓋。

Pull Request 到底是什麼？

PR 不是把程式直接塞進老師的專案。它會先建立一個比較頁面，列出學員改了哪些檔案；老師看完後可以留言、要求修改，或按下 Merge 接受作品。

BASE｜變更要收進哪裡 yumaoshih/ai-workshop-starters main
← PULL REQUEST ← ↑ PULL REQUEST ↑
HEAD｜變更從哪裡送出 你的帳號/ai-workshop-starters main

記憶法：base 是老師的收件匣，head 是學員的寄件匣。箭頭要朝向老師的專案。

學員：送出 PR

  1. 確認作品已 Commit 到自己的 Fork。
  2. 回到老師的原始 Repository。
  3. 按 Compare & pull request。沒有看到時，進入 Pull requests → New pull request → compare across forks。
  4. 確認 base 是老師的 main，head 是自己的 Fork。
  5. 填寫作品名稱與修改內容，按 Create pull request。

老師：Review 與 Merge

  1. 到原始 Repository 的 Pull requests 開啟投稿。
  2. 查看 Files changed，確認只修改該學員自己的投稿資料夾。
  3. 需要調整就留言；沒問題就選擇 Approve。
  4. 按 Merge pull request，再按 Confirm merge。
  5. Merge 完成後，作品才正式進入老師的 main。

課堂分工：學員負責做到 Create pull request；你負責 Review 與 Merge。學員不需要擁有老師 Repository 的寫入權限。
